## 0. Әдістеме және шектеулер

### 0.1 Ең маңызды шектеу: вендорлардың беттері ашылмады

Бұл сессияда **WebFetch және кез келген тікелей HTTP сұрау ұйымның egress
саясатымен толық бұғатталған**. Тексерілген нақты қателер:

| Домен | Қате |
|---|---|
| `joinposter.com` | `EGRESS_BLOCKED` |
| `dev.joinposter.com` | `EGRESS_BLOCKED` |
| `posterpos.kz` | `EGRESS_BLOCKED` |
| `paloma365.kz` | `EGRESS_BLOCKED` |
| `apps.apple.com` | `EGRESS_BLOCKED` |
| `en.wikipedia.org` | `EGRESS_BLOCKED` |
| `curl https://joinposter.com/pricing` | `curl: (56) CONNECT tunnel failed, response 403` |

Яғни блок белгілі бір сайтқа емес, **барлық шығыс трафикке** қатысты.
Жалғыз жұмыс істейтін құрал — `WebSearch`.

### 0.2 Екінші шектеу: іздеу лимиті

Сессияның `WebSearch` бюджеті (200 сұрау, барлық субагенттерге ортақ)
мен ~30 сұрау жасағаннан кейін таусылды. Тапсырмада көрсетілген 25–35
сұрау орындалды, бірақ **жоспарланған қосымша сұраулар (App Store /
Google Play пікірлері, Frontol, Mirabelle, Smart Kassa, Jowi бағасы)
орындалмай қалды**.

### 0.3 Таңбалау конвенциясы (осы есепте)

Тапсырма шартындағы таңбаларды сақтаймын, бірақ 0.1-ге байланысты
**маңызды түзетумен**:

- `[РАСТАЛҒАН]` — дереккөз вендордың өз домені (ресми сайт /
  құжаттама / баға беті), нақты URL келтірілген, әрі тұжырым сол беттің
  іздеу жүйесі берген сипаттамасында тікелей айтылған.
  **⚠ Бет өз көзіммен ашылмады** — бұл «вендор дереккөзі, жанама қолжетім».
  Фаза 2-ге дейін бұлардың бәрін адам қайта тексеруі керек.
- `[ЖАНАМА]` — үшінші тарап: шолу сайты, дилер, блог, форум, жаңалық,
  бәсекелестің салыстыру мақаласы.
- `[БОЛЖАМ]` — менің қорытындым, тікелей дереккөз жоқ.
- `[БҰҒАТТАЛҒАН]` — тексеру үшін демо-аккаунт, сату бөліміне сұрау,
  немесе egress рұқсаты керек.

### 0.4 Тағы үш ескерту

1. **Бәсекелестің салыстыру мақаласы — бейтарап дереккөз емес.**
   Нарықтағы «ТОП-5 / ТОП-6 жүйелер» мақалаларының бір бөлігі
   `joinposter.kz` доменінде, яғни Poster-дің өзі жазған. iiko-ның
   «27 300 ₸» деген саны негізінен сол мақалалардан таралған көрінеді.
   Төмендегі баға бөлімінде бұл бөлек белгіленген.
2. **Ресей мен Қазақстан тарифтері әртүрлі.** ₽ бағалары ҚР-ға
   қолданылмайды, тек масштаб түсіну үшін берілген.
3. **«Офлайн режимі бар» ≠ офлайн-first сәулет.** Есепте маркетинг
   мәлімдемесі мен техникалық сипаттама бөлек жолдарда тұр.

## 2. Poster (joinposter.com / joinposter.kz)

### 2.1 Позициялау және сегмент
Бұлттық HoReCa жүйесі, кофеханадан желіге дейін. Қазақстанда белсенді
өкілдігі бар: `joinposter.kz` (ресми KZ домені), `posterpos.kz`,
`poster24.kz`, `upw.kz/poster` (дилерлер), Instagram `@joinposter.kz`,
YouTube «Poster POS Kazakhstan». [ЖАНАМА]
Бір аккаунтқа қосылатын нүкте саны шектелмейді. [ЖАНАМА —
іздеу қорытындысы, joinposter.kz]

### 2.2 Баға моделі

### 2.3 Ашық API
- Web API v3 құжаттамасы: `https://dev.joinposter.com/en/docs/v3/start/index`

  деректі алу, **webhook-қа жазылу**, POS-кассаға және басқару панеліне

  `https://github.com/joinposter` [РАСТАЛҒАН]

  (меню, техкарта, қалдық, клиент базасы) — миграция утилитасы жазуға
  болады; (б) webhook моделін үйрену — біздің sync engine-ге ұқсас
  мәселелерді олар қалай шешкенін көру.

### 2.4 Офлайн режимі — техникалық
Дереккөздер (бәрі вендордың өз білім базасы):
- `https://knowledge-base.joinposter.com/ru/does-poster-work-offline`
- `https://knowledge-base.joinposter.com/ru/how-pos-sync-works`
- `https://knowledge-base.joinposter.com/ru/what-to-do-if-poster-pos-servers-are-down`

**Офлайнда ІСТЕЙДІ** [РАСТАЛҒАН]: чек құру, әдеттегідей жұмыс;
тапсырыстар терминалда сақталады, байланыс қалпына келгенде
автоматты синхрондалады.

**Офлайнда ІСТЕМЕЙДІ** [РАСТАЛҒАН]:
- онлайн-тапсырыстар терминалға түспейді;
- **терминалдар арасында, әкімші панелімен және Poster Boss-пен
  синхрондау болмайды** (яғни 2–3 жұмыс орны бір-бірін көрмейді);
- сатулар байланыс қалпына келгенше әкімші панеліне жетпейді;
- **принтерлер роутер арқылы қосылған болса — чек те, өтінім де
  басылмайды**.

**Ескерту (вендордың өзінің талабы):** офлайнда кэшті тазартуға,
қосымшаны қайта іске қосуға немесе өшіруге БОЛМАЙДЫ — әйтпесе деректер
жоғалады. [РАСТАЛҒАН]

**Автономды жұмыстың уақыт шегі құжатта көрсетілмеген** — тапқан
дереккөздердің ешқайсысында сан жоқ. [РАСТАЛҒАН — жоқтығы бойынша]

> 💡 Бұл — **бізге тікелей ұту нүктесі**. «Кэшті тазартпаңыз» деген
> ескерту жергілікті БД емес, браузер/қосымша кэші деңгейінде
> сақталатынын меңзейді. Біздің SQLite (drift) + event sourcing
> сәулетімізде мұндай ескерту мүлдем қажет емес. [БОЛЖАМ]

  немесе қазақша+ағылшынша береді. [ЖАНАМА]

Нақты айтылғаны:

- «Ең «ескі» автономды чек 72 сағаттан асып кетпеуі керек» — яғни
  таймер соңғы синхрондаудан емес, **ең ескі жіберілмеген чектен**
  саналады. ⚠ Бұл өте нақты, сирек құжатталған талап.
- Автономды режимде әр чекке **бірегей нөмір беріледі — «автономды
  фискалдық белгі» (АФБ)**, ол чекте басылады; чекте «Автономный»
  деген белгі болады. [РАСТАЛҒАН —
  `https://oofd.kz/faq/8`, `https://dknews.kz/ru/finansy/358011-...`]
- Автономды режимде **«Ауысым жабу» + Z-есеп басу қамтамасыз етіледі**;
  ККМ ауысым жабу сұранымын **автономды кезекке қосады** және байланыс
  қалпына келгенде **Z-есеп алынған күн-уақыт белгісімен** серверге
  береді. [РАСТАЛҒАН]
- Автономды кезеңдегі барлық чек ККМ-нің фискалдық деректер жинақтағышында
  сақталады, байланыс қалпына келгенде ОФД-ға беріледі. [РАСТАЛҒАН]
